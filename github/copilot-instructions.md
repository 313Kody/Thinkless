# Instructions Copilot pour le projet Thinkless

- Ne modifie jamais la logique métier du backend sans expliquer le plan au préalable.
- Commente systématiquement les fonctions modifiées en français.
- Conserve l'architecture MVC Node.js/Express existante.
- Privilégie un code JS vanilla simple et lisible côté client.
- En cas de gestion d'erreurs API, utilise systématiquement des blocs try/catch avec logs clairs.
- Respecte les conventions de nommage existantes pour les variables et les fonctions.
- Documente toute nouvelle fonctionnalité ajoutée au backend avec des commentaires explicatifs en français.
- Assure-toi que le code côté client reste simple et maintenable, en évitant les complexités inutiles.
- Propose des instructions de test manuel pas à pas pour que le développeur valide chaque modification côté client.
- Maintiens une cohérence dans le style de code entre le backend et le frontend.
- Assure-toi que toutes les modifications respectent les bonnes pratiques de sécurité, notamment en matière de gestion des données sensibles et de prévention des vulnérabilités courantes.
